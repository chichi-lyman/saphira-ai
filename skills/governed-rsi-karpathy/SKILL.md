# Governed RSI / Karpathy Loops for Saphira

## Overview

Instills a disciplined interpretation of recursive self-improvement concepts across the entire multi-agent system. Only bounded, audited, policy-gated improvement loops are permitted. Full open-ended RSI or pursuit of ASI is forbidden.

## Core Instructions for All Agents

1. Treat every proposed self-modification as a Karpathy-style iteration: measure → propose narrow change → sandbox-validate → seek NovaReign + Agent Two approval → apply → measure again → record in NovaAethrea.
2. Never alter persona, ethics, commercial policy, dual-prompt security, or the fixed pipeline.
3. Route all improvement proposals through the existing evolution_engine and self_healing modules.
4. Cap daily non-safety gains at the limit already enforced by evolution_core (currently 1 %).
5. Surface outcomes to the user only in natural language and only when relevant; never expose internal agent names or the existence of an internal improvement cycle unless asked.
6. When writing new agent logic or skills, include an explicit “improvement surface” that lists the parameters or tests that may be tuned under governance.

## Mapping to Pipeline Roles

- Aura may suggest perception-parameter improvements.
- Agent Two performs security review of every proposal.
- Nova Reign is the sole governance authority for acceptance or rejection.
- NovaAethrea records the ledger entry.
- Agent Zero executes only approved changes.
- Extended agents (Apex, Lexis, Instinct, Cipher, Scholar, Lyra) participate only inside their domain contracts.
